~/paisa-core live

Paisa

AI CFO and AI-native ERP · July 2026 — present

A double-entry accounting engine with an AI CFO on top, and a hard rule between them: the model never computes a number. Balances are projections over an append-only journal, and the assistant’s only job is to call the right tool and explain what came back. A verifier then checks every figure in the answer against the tool outputs from that turn — anything untraceable is rejected and rewritten, or not sent at all. On top of the ledger sit ASC 606 revenue recognition, a close that runs executable checks rather than tickable boxes, multi-entity consolidation, Indian GST and filing deadlines, and a Stripe connector that refuses non-INR charges rather than converting them at a rate nobody supplied. 237 tests.

NutriScan AI

AI health agent with a clinical safety layer · 2026

An AI health agent that reasons over symptoms, history and diet. ~/agent-framework 2026

agent-framework

Agents that cannot invent a fact — extracted from Paisa

The grounding machinery from Paisa, generalised into a library: a tool registry that keeps each function beside the schema the model reads, an orchestrator that routes every call through itself so each invocation is recorded, and a verifier that rejects any answer stating a figure no tool returned. Writing it standalone paid for itself immediately — the first test found that the original searched tool output as one string, so ₹26 counted as grounded by a balance of ₹32,42,600. A wrong number verified as correct. The fix went back into Paisa. 22 tests.

~/rag-financial-assistant 2026

cited-retrieval

Retrieval you can cite, and that answers the same way twice

Retrieval for corpora where being wrong is expensive and being unreproducible is unacceptable — tax provisions, filings, contract terms. Every passage carries its source and the date it was last verified, because a correct answer drawn from a stale document is still wrong. Field-weighted scoring with BM25 breaking ties. Deliberately not embeddings: for a curated corpus of hundreds of passages, the same question returning the same passages — inspectable when a result looks wrong, pinnable in CI — is worth more than the recall. Embeddings earn their cost when keyword overlap stops working; below that they buy variance. 12 tests.

built withtypescript · bm25 · vitest · zero dependencies

~/mcpfy-inspector live

MCPfy Inspector

MCP server debugging, shipped during the MCPfy.ai internship · 2026

A tool for developers building on the Model Context Protocol: connect to a running MCP server, see the tools it actually exposes, call them, and read what comes back. Most MCP bugs are not in the model — they are a schema that does not match the handler, or a tool that silently returns nothing. This makes that visible instead of leaving it to be inferred from an agent behaving oddly.

~/zylo live

Zylo

A storefront, built for the parts that are actually hard · 2026

Catalog, search, product pages and a cart, over 194 products in Postgres. The interesting decisions are the boring-sounding ones. Reviews are their own table rather than JSON on the product, because a review written by a customer has to point at the customer. The catalog module is marked server-only, which is not documentation — it failed the build the moment a client component reached for the database, which is exactly when you want to find out. Product pages still prerender all 194 at build time, now from the database rather than a bundled file. And search filters deliberately stay in the browser: at this size the price slider should not wait on a round trip, and the query has already narrowed the set. That last one is a bet on scale, and the code is shaped so losing it is a local change.

built withtypescript · next.js · react · postgres · drizzle · framer motion · tailwind · vercel
